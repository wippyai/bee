## Current behavior before changes

`bee hive invite` asks the running Lua supervisor to mint a 15-minute, single-use ID and secret. Native `runHive` reads the owner's private rendezvous descriptor and prints `bee-hive://ID:SECRET@IP:PORT/NODE?key=SHA256-OF-IDENTITY-KEY`. The join listener is a random TCP port, bound on the mesh address family. `bee hive join` is allowed only while the joining owner is stopped. It dials the sole literal IP endpoint using TLS 1.3, pins the server identity key before disclosing the secret, and proves its own identity key. The inviter redeems through the supervisor, pins the joiner's key, certifies its mesh leaf, and sends one gossip address, a mesh secret, and authorities. The joiner persists that one seed. At next boot, each owner binds gossip/internode sockets and advertises one address; a joined owner seeds the inviter's gossip address. A periodic native task records one authenticated peer gossip address for later boots. Lua supervisors establish their own session after runtime mesh membership and name discovery. `bee hive peers` reports only the supervisor session state.

Feature 76fd02b added `BEE_MESH_ADDRESS`: one assigned, non-loopback IP selected for owner startup and the joining command. The owner binds on all interfaces of that IP family but advertises only the selected address; same-host clients use a separate loopback descriptor alias. Without the variable, owner gossip, internode transport, and join listener all advertise `127.0.0.1`.

## Failure cases

An invite's only IP can be unreachable from a different LAN, tailnet, container, VM, or WSL2 NAT guest. IPv6 or MagicDNS alternatives cannot be carried or tried. An ordinary remote invite without `BEE_MESH_ADDRESS` advertises loopback, so even a successful local redemption cannot establish a remote mesh. A forwarded join port alone is insufficient: gossip and internode transport need reachable advertised endpoints too. WSL2 NAT's guest `172.x` address is ordinarily inaccessible from another machine; Windows host portproxy/firewall or mirrored networking is needed. A bridge address is likewise only reachable within its bridge unless forwarded. The current single mesh advertisement cannot express different paths for different peers. The joiner receives one seed and the runtime has no Bee API to report its authenticated connection's actual endpoint, exchange observed addresses, or retry a bounded pool of peer candidates on reconnect. The inviter cannot initiate an unreachable joiner's first handshake from a one-way offline invite without learning the joiner's address through another rendezvous path.

## Runtime PR proposal (needed for the full requirement)

Extend runtime mesh membership/transport with a bounded, typed list of advertised gossip and internode candidates per node, including family and scope, and authenticated observed endpoints. Try candidates concurrently with a small stagger, authenticate the pinned node identity before selecting a connection, retain the winning path for diagnostics, and retry the full current candidate set plus learned addresses on reconnect. Publish candidates and learned paths only as transport hints; continue using Bee's exact peer key pin and host admission for authority. Permit the already authenticated join channel to deliver the joiner's candidate list to the inviter and trigger a reverse dial when the forward path fails. A fully unreachable inviter still needs a mutually reachable relay or an operator-configured Windows portproxy: a one-way invite cannot convey the joiner's future address to an offline inviter.

## Bee implementation in this branch

The invite remains one line and retains the pinned Ed25519 identity. It now carries up to eight canonical, typed IP/MagicDNS alternatives selected from active interfaces, Tailscale status, and optional `BEE_HIVE_ADDRESSES`. Loopback and link-local alternatives are excluded. The joiner races TLS handshakes and discloses the single-use secret only on the first identity-verified connection. Exhausted candidates produce per-endpoint errors. The actual authenticated TCP peer IP is recorded as `join_path` and used with the returned gossip port as the initial seed. Mesh leaves include the selected IP and a bounded set of explicit/interface IPs. WSL2 NAT output names the live ports and explains mirrored networking and TCP/UDP forwarding limits. A failed join against a private VM address includes a forwarding hint.

This does not implement the runtime proposal above. `bee hive peers` still shows supervisor session state, not the live internode socket path. Runtime reconnect still uses one advertised address and recorded peer gossip addresses, rather than a candidate pool. Reverse connect cannot bootstrap an unreachable inviter from this one-way token alone. An invite through a Windows TCP portproxy still needs UDP gossip forwarding and a usable mesh advertisement.
